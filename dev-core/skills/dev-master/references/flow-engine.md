# 流程引擎

> 本文件是 `dev-master` 单一流程的执行机制：怎么起、怎么记任务、阶段怎么交接、什么时候要用户确认、
> 产物落在哪、中断了怎么续。**阶段内容细则在 `stages/` 下，本文件只管机制。**

## Step 0：初始化（起流程必问，AskUserQuestion 单次最多 4 问）

**问题1｜现在手头有什么？**（决定起点）
- 只有想法／PRD（→ 阶段 1，先转写 SRS）
- 已有 SRS 需求规格说明书（→ 阶段 2 或直接 5）
- SRS + 设计文档都齐了（→ 阶段 5 / 6）
- 已有代码库，要加功能（→ 迭代裁剪）
- 代码已写完，只要审计（→ 阶段 11）
- 代码先行、文档缺失（→ 反向补文档裁剪）

**问题2｜走到哪一步？**（裁剪，细则见 `tailoring.md`）
全量 0→12 / 三端全栈 0-1 / 有 SRS 直接开工 5→12 / 只要文档链 1-4 / 迭代 / 单页面 / 上线体检 / 反向补文档 / 自定义

**问题3｜阶段 7 档位？**（这题决定整条流程的重量）
- **`page-generator`（默认档）** — 在已有项目里按 SRS 加页面，快
- **`dev-fullstack-product`（深度档）** — 移动端 + 管理端 + 后端三端 0-1，自带技术栈确认、三轮真跑测试、12 角色专家评审
- 用户已经说了「三端」「APP 加后台」「整套系统」「从 0 到 1」→ **直接按深度档，不要再问**

**问题4｜交付模式？**（默认「标准」，向下游传 `DELIVERY_MODE`）

| 档 | 审查强度 | 确认节点 |
|---|---|---|
| 快速 | 单轮自查 | 基本不停，只在阶段 1 和 7 停 |
| **标准**（默认） | 产出后自查 + 关键项抽检 | 阶段 1、4、5、7、11 必须确认 |
| 严格 | 每个产出独立审查一轮 | 每阶段都确认，阶段 7 逐模块确认 |

**自动升档**：用户消息里出现「正式交付」「验收」「上线」「提测」「完整审查」「严格模式」→
**整任务升严格**，直到用户另行声明。

> 用户已经把起点、范围说清楚了，**不要为了走流程再问一遍**。四问是补缺，不是仪式。

## 任务清单

Step 0 之后**立刻建任务清单**，一个阶段一条，格式：

```
[阶段 N] 名称 — 技能(档位) — 状态(待办/进行中/已完成/已跳过) — 产出路径
```

- 跳过的阶段**保留在清单里**并标「已跳过（理由）」——断点续跑靠这个判断
- 阶段编号永不改变，不要因为裁剪掉了前几个阶段就重新编号

## 阶段间传递门禁

**每个阶段的 `artifact.glob` 与 `gate` 条目写在 `../workflow-catalog.yaml` 里，按那份执行。**
下表是跨阶段的强依赖摘要——进入下一阶段前，**先验上一阶段的产出真的存在**（按 glob，不要写死文件名）：

| 进入阶段 | 必须已存在 | 验法 |
|---|---|---|
| 2,3,4,5,6,7,8 | `SPEC_SOURCE`（合格 SRS） | `ls dev/SRS/*.md docs/SRS/*.md`（都没有再看 `prd/SRS/`）+ 内容角色校验，见 `../common/prd-to-srs-gate.md` §2 |
| 4 | 概要设计 | `ls dev/**/*概要设计*.md docs/**/*概要设计*.md` |
| 5 | 功能清单 或 SRS 功能章节 | 二者有其一即可 |
| 7 | 详细设计（表结构+接口）或 SRS 字段级章节 | 缺则回阶段 4 |
| 9 | 可运行的代码 | 真的起一次服务，不是看目录存在 |
| 11 | 测试通过记录 | 阶段 9/10 的报告 |
| 12 | 阶段 11 无致命项 | 有致命项先整改 |

门禁不过**不要硬着头皮往下跑**：说清缺什么、补哪一步、回到哪个阶段。

## 并行规则

- **可并行**：阶段 2（功能清单）与阶段 3（概要设计）；阶段 9（用例编写）与阶段 7 后半段
- **禁止并行**：阶段 3 → 4（详细设计依赖概要的模块划分）、阶段 7 → 9 的真跑测试（代码没跑起来测不了）
- 并行时在任务清单里标 `∥`，两条都完成才进下一阶段

## 落盘目录约定

**唯一落盘根是 `dev/`**（`DEV_DOC_ROOT`）。研发链产出一律写 `dev/`；`docs/` 只读兼容。

| 类型 | 路径 |
|---|---|
| SRS | `dev/SRS/` |
| 功能清单 / 概要设计 / 详细设计 / 错误码表 | `dev/design/`（文件名按各技能自身命名） |
| 交付计划 | `dev/plan/delivery-plan-{项目名}.md` |
| 测试用例 / 测试报告 / 缺陷闭环 | `dev/test/` |
| 上线审计报告 / 12 角色评审报告 | `dev/reports/` |
| 操作手册 / 发版说明 | `dev/release/` |
| 流程进度 | `dev/dev-master-{项目名}.md` |
| 图片 | 各文档同级 `images/`（如 `dev/design/images/`） |
| PRD（上游 `pm-master` 留下的，只读） | `prd/PRD/`（旧项目 `docs/PRD/`） |
| 产品链其余文档（战略/调研/画像/优先级/路线图/可研，只读） | `prd/**` |
| 老项目历史文档（只读兼容） | `docs/**` |
| 设计稿 | `Prototype/<项目slug>/` |
| 代码 | `src/` 或各子项目目录 |
| 数据库迁移脚本 | `migrations/` 或 `db/` |

三条执行要求：

- **阶段技能的默认落点是 `docs/`，调用时必须显式传目标路径**（「SRS 落 `dev/SRS/`」
  「详细设计落 `dev/design/`」），不要写完再搬——搬家会断图片相对路径与交叉引用
- **读的时候三处都看**：`dev/` 优先 → `prd/`（上游 PRD 与产品文档）→ `docs/**` 兜底（存量项目）
- **老项目命中 `docs/` 里的历史产出 → 原地续用不搬家**，在进度存档里登记真实路径；
  用户明确要求迁移才迁，迁移时 `images/` 一起搬并回改全部相对引用

## 进度存档与断点续跑

全程维护 `dev/dev-master-{项目名}.md`：裁剪区间、档位、交付模式、任务清单及状态、
`SPEC_SOURCE`、各阶段产出路径（真实路径，落在 `docs/` 的老文档照实记）、遗留项。**每个阶段结束写回**。

**重新进入本技能时先读它**：命中就把清单摘要念给用户，问「续跑 / 重来 / 改裁剪」，
不要从 Step 0 重问一遍。文件不存在再走 Step 0。

## 确认节点

按 `DELIVERY_MODE` 停：

| 阶段 | 快速 | 标准 | 严格 |
|---|---|---|---|
| 1 规格真源 | 停 | 停 | 停 |
| 4 详细设计 | — | 停 | 停 |
| 5 交付规划 | — | 停 | 停 |
| 7 编码实现 | 停（整体一次） | 停（每模块） | 停（每模块 + 逐页对设计稿） |
| 11 上线审计 | — | 停 | 停 |
| 其余 | — | — | 停 |

用户说「不用确认了 / 一直做 / 自动执行」→ 连跑，但**每阶段仍按输出格式汇报**，只是不等待。

## 汇报格式

每阶段结束固定输出（`../SKILL.md` 末尾那八行），其中「门禁检查」一栏必须写清
**下一阶段需要的输入是否齐备**，不齐备就停。

## 方向盘在谁手里（阶段 5/7 的双编排器问题）

`delivery-plan` 的 **Step D 自动执行模式**本身就是个 orchestrator——它会按交付计划连续实现所有功能、
不停不问。这跟本流程是两套方向盘，必须先定谁开：

| 情形 | 谁开 | 进度写哪 |
|---|---|---|
| 走本流程（默认） | **dev-master**。阶段 5 只用 `delivery-plan` 的 A/B/C 模式（生成／查看／更新），阶段 7 的连跑由本流程按确认节点驱动 | `dev/dev-master-*.md` 为主，交付计划的状态位同步回写 |
| 用户直接对 `delivery-plan` 说「按计划实现所有功能／一直实现」 | **delivery-plan Step D**，本流程**退位** | 交付计划文件为主；在 `dev/dev-master-*.md` 记一行「阶段 7 由 delivery-plan 自动执行模式接管」 |

**禁止**：两边同时跑连跑模式（会出现同一个功能被实现两遍、状态位互相覆盖）。

## 不要做的事

- 不要自己动手写本该由阶段技能产出的内容（你是编排器，不是执行器）
- 不要跳过阶段 1 的真源门禁，也不要把 PRD 当 SRS 用
- 不要在阶段 7 选了深度档之后，又把阶段 9–11 原封不动跑一遍（改为校验它的产出）
- 不要同时起 `pm-master` 和本流程的两套任务清单
- 不要把研发链产出写回 `docs/`（那是产品侧与只读兼容区），也不要为了统一路径去搬老项目已有的 `docs/` 文档
