# 阶段 9：测试

**技能**：`pm-test-cases`（用例）+ `webapp-testing`（真跑）｜ 深度档 `test-driven-development`
**产出**：`dev/test/`（用例表 · 执行报告 · 缺陷清单；截图等证据落 `dev/test/images/`）

> **与 `pm-master` 阶段7 不是同一份**：那边出的是未执行的验收用例（该验哪些），
> 本阶段出的是真跑过的执行报告（实际跑通没有）。`prd/test/` 下有用例可以拿来当输入，
> **但不能拿它代替本阶段的执行证据**。分工表见 `../../SKILL.md`「重叠产物」。

## 做什么
1. **出用例**：`pm-test-cases` 从 SRS 生成功能/边界/异常/权限四类用例，带编号与预期结果
2. **真跑**：`webapp-testing` 驱动 Web 端逐条执行；移动端用模拟器工具；后端用真实 HTTP 调用
3. **出报告**：用例表 + 执行统计（通过/失败/阻塞/未执行）+ 缺陷清单 + 遗留风险

## 铁律
**只写真正执行过的结果。** 没跑的标「未执行」，跑挂的标「失败」并贴关键报错。
把「预期应当通过」写成通过，比不测更有害。

## 深度档
`test-driven-development`：先写测试再写实现，适用于后端核心业务逻辑；
选它时本阶段部分前移到阶段 7 内部。

## 阶段 7 走了深度档时
不重跑，改为**校验** `dev-fullstack-product` 的三轮测试报告：
用例表齐不齐、有没有「未执行」被写成「通过」、致命/严重缺陷是否全部闭环。

## 判据以 `references/delivery-review.md` §7 为准
用例分层（单元/接口/集成/E2E）、三类覆盖（正常/异常/边界）、断言完整性、
用例独立可重跑、Mock 与真实切换、覆盖率阈值、CI 触发与回归报告——**逐条对照 §11.4 那张表**。

两条最常漏的：
- **断言必须含落库结果**，只断言"返回 200 / 无异常"不算通过；
- **用例必须单跑通过且连跑两次结果一致**，互相依赖的用例等于没有测试资产。
