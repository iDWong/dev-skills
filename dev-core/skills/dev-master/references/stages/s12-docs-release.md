# 阶段 12：文档与发版

**技能**：`pm-operation-manual` + `pm-release-notes` + `release-rollout` + `finishing-branch`
**产出**：`dev/release/`（手册 · 发版说明 · 发布与回滚预案；`CHANGELOG.md` 仍在仓库根）

> **与 `pm-master` 阶段8/9 不是同一份**：那边照需求文档写、面向最终用户；
> 本阶段照真实实现写、另含发布与回滚预案。分工表见 `../../SKILL.md`「重叠产物」。

## 做什么
1. **操作手册** `pm-operation-manual`：基于 SRS 与已实现页面生成管理员手册 / 终端用户指南
2. **发版说明** `pm-release-notes`：本次变更、新增功能、修复、已知问题、升级注意事项（**面向用户**）
3. **发布与回滚预案** `release-rollout`：变更面五类盘点 → 灰度批次与开关 → 监控指标与阈值 →
   回滚触发条件与步骤 → **演练记录**（**面向自己人**）。数据迁移按 expand-contract 拆，
   不可逆操作单列并写明备份位置与确认人
4. **分支收尾** `finishing-branch`：验证测试 → 检测环境 → merge / PR / 保留 / 丢弃 四选一

## Word 导出的三个坑（踩过的）
- **导出读的是启动那一刻的 md**：任何编辑之后都要重新导出，否则 docx 静默过期 → **导出永远放最后**
- **图片文件名含中文会静默丢图**：导出后必须验 `unzip -l x.docx | grep -c 'word/media/'`，数字等于图片张数
- 改过文案的图必须**重渲**：源文件与图片 mtime 对不上就是过期图

## 门禁（收尾判据）
- [ ] 手册、发版说明、发布与回滚预案三份都已落 `dev/release/`
- [ ] 回滚步骤**演练过一次**并记了实际耗时与 RTO（不发版的内部项目可豁免，须注明）
- [ ] Word 导出放在所有编辑之后，且验过 `word/media` 图片数与图片张数一致
- [ ] 交付物清单七项齐备（见上一节）
- [ ] 分支已按 `finishing-branch` 的四选一处理完，没有悬空分支

## 可跳过
内部项目不发版时，可只做手册与分支收尾，跳过发版说明与回滚预案（**要在进度存档里注明**）。
**交付给真实用户时整阶段不能跳**，回滚预案尤其不能省。
