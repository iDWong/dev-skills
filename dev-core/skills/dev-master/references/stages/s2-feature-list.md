# 阶段 2：功能清单

**技能**：`feature-list` ｜ **产出**：`dev/design/*功能清单*.md` / `.xlsx`（该技能自身的默认落点就是这儿）

## 做什么
从 `SPEC_SOURCE`（+ 可研报告，若有）提取功能项，输出模块 → 功能 → 子功能三级清单，
每项带：编号、所属模块、功能名、简述、优先级、涉及端（移动端/管理端/后端）。

## 要点
- **编号规则定一次就不改**：后续阶段 5 的交付计划、阶段 9 的测试用例都靠它对齐
- 涉及端一列是三端项目的关键，阶段 5 排顺序、阶段 7 分模块都读它
- 需要 xlsx 交付时走 `common/` 的导出链

## 门禁
- [ ] 清单条数与 SRS 功能章节对得上，没有凭空多出来的功能
- [ ] 每条都能在 SRS 里找到对应段落（找不到的标「待确认」并问用户）

## 可跳过
SRS 功能章节已成体系且不需要单独交付物 → 跳过，阶段 5 直接读 SRS。
