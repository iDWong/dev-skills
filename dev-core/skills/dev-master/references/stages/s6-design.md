# 阶段 6：界面与设计稿

**技能**：`ui-ux-pro-max`（设计系统 + 材质与层级 + 多端规则，设计侧只此一个）｜ **产出**：`design-system/<项目slug>/`

## 做什么
读 PRD（主）+ SRS（补字段与规则）产出可点可交互的设计稿：三张 iframe 预览墙
（移动 393×852 / 官网 1280×900 / 后台 1440×900），点卡进全屏，全屏页右下角需求标注。
**不做出稿帧**：所有状态与分支都要靠真实操作在流程里走到（契约铁律 8）。
两份必交文档：`FLOWS.md`（流程清单）与 `HANDOFF.md`（工程师对接清单八节 + `tokens.json`）。

## 要点
- **本流程里通常只有 SRS**（PRD 属产品侧 `pm-master` 链路）。`ui-ux-pro-max` 的交付契约（`ui-ux-pro-max/references/prototype-delivery.md` 的缺件表）已为此开了豁免：**以 SRS 为唯一真源出稿**，索引页注明「无 PRD，页面清单与文案取自 SRS」。**不要因为缺 PRD 就去跑 `pm-prd-spec`**——那是产品侧技能，研发流程里没有这一环，硬等会把本阶段卡死
- 设计令牌（色彩/字号/间距/圆角/阴影）在这一阶段定死 —— 阶段 7 的「1:1 对齐」以它为基准
- 八种交互状态（default/hover/active/focus/disabled/loading/empty/error）设计稿要覆盖；
  没覆盖的由阶段 7 自动补全并记入 `README-DEV.md` 的「设计补全项」

## 门禁（进阶段 7 前）
- [ ] 设计令牌成文，阶段 7 能直接取色值/字号
- [ ] 关键页面（登录、列表、详情、表单）都有稿
- [ ] `FLOWS.md` 已生成且逐条走通；`grep -l 'data-setframe' design-system/*/*.html` 为空
- [ ] `HANDOFF.md` 八节齐全 + `tokens.json` 已落盘；末尾十条高频漏项自查全绿
- [ ] 覆盖多端时：平台差异走独立页面（无切帧）、`CONSISTENCY.md` 已交且冲突项已统一
- [ ] 契约「清单反查九条」的机检输出 OK（组件八态 / 四断点 / 动效令牌 / 变量同源 / 校验规则 / 极限数据 / 切图导出）

## 可跳过
已有设计稿，或纯后端项目 → 跳过。但用户要求「1:1 还原」而没有稿时**不能跳**。
