# 测试与验收协议（阶段 4）

## 0. 通过标准

三轮**真实执行**的测试全部跑完，且第 3 轮「主流程 + 边界 + 异常」全部通过。
未跑通就继续第 4、5… 轮。**不得以「非阻塞」为由提前宣布通过。**

## 1. 真跑，不是纸面推演

| 端 | 驱动方式 |
|---|---|
| 管理端 / Web H5 | Browser 工具：`preview_start` 起服务 → `read_page` / `computer` 点击输入 → `read_console_messages` + `read_network_requests` 验错 → 截图留证 |
| 移动端 iOS | iOS Simulator 工具：`attach` → 构建安装 → `inspect` 读控件 → `tap`/`text` 驱动 → 截图留证 |
| 移动端 Android / 小程序 | 对应模拟器或开发者工具；无法驱动时明确写「本轮该端为人工/未执行」，不得伪造结果 |
| 后端 | 单元/集成测试 + 真实 HTTP 调用（curl / httpie / Playwright API），核对响应体与数据库落库结果 |

## 2. 单元与集成测试

| 层 | 覆盖要求 |
|---|---|
| 后端 service/domain | 核心业务逻辑分支全覆盖，含异常分支 |
| 后端 API | 每个接口至少：正常、参数非法、未授权、越权、不存在 五个用例 |
| 前端组件 | 有状态逻辑的组件与工具函数 |
| E2E | 登录 + 每条主流程至少一条 happy path |

覆盖率阈值在阶段 1 与用户约定（默认：后端核心模块 ≥70% 行覆盖，工具函数 ≥90%）。

## 3. 测试环境部署检查清单

- [ ] `docker compose up` 一次起全套（DB、缓存、后端、管理端、网关），**真的跑一次**
- [ ] 端口无冲突；冲突时在 compose 里改并写进 README
- [ ] 环境变量齐全，`.env.example` 与代码里实际读取的变量**逐个对得上**
- [ ] 数据库初始化 + 迁移脚本可重复执行（跑两次不报错）
- [ ] 种子数据脚本可重复执行（幂等或先清后插）
- [ ] Nginx / 网关路由与跨域配置正确
- [ ] 健康检查端点可访问；容器重启后服务自恢复
- [ ] 前端构建产物可被正确服务（路由 fallback、静态资源路径）
- [ ] 移动端可打出可安装包或可在模拟器运行

## 5. 每轮测试用例表模板

| 用例ID | 端 | 模块 | 用例名 | 前置条件 | 步骤 | 预期结果 | 实际结果 | 结论 | 缺陷ID |
|---|---|---|---|---|---|---|---|---|---|
| TC-001 | 管理端 | 认证 | 正确账密登录 | 账号已存在 | 1.打开登录页 2.输入 3.提交 | 跳转首页，菜单按角色渲染 | | 通过/失败/阻塞/未执行 | |

**结论只能填真实执行结果。** 没跑的填「未执行」，不要填「通过」。

## 6. 缺陷清单模板

| 缺陷ID | 严重级 | 端 | 模块 | 现象 | 复现步骤 | 根因 | 修复方案 | 修复提交 | 回归结论 |
|---|---|---|---|---|---|---|---|---|---|
| BUG-001 | 致命/严重/一般/轻微 | | | | | | | | |

严重级定义：**致命**=主流程不可用/数据错误/安全漏洞；**严重**=功能不可用有绕行；
**一般**=体验受损；**轻微**=文案样式。致命与严重**必须本轮修完**。

## 7. 三轮范围

| 轮次 | 范围 | 重点 |
|---|---|---|
| 第 1 轮 全覆盖 | 每个页面、每个功能、每个按钮、每个表单、每条跳转、每条异常路径 | 广度，把问题全炸出来 |
| 第 2 轮 回归 | 第 1 轮全部缺陷 + 其关联路径 + 各角色账号权限矩阵 | 验修复、防回归、查越权 |
| 第 3 轮 全量复测 | 全量重跑主流程 + 边界（空/极值/超长/特殊字符）+ 异常（断网/超时/并发/重复提交） | 确认整体可交付 |

## 8. 每轮输出（缺一不可）

1. 测试用例表（含执行结果）
2. 执行统计：总数 / 通过 / 失败 / 阻塞 / 未执行 + 通过率
3. 缺陷清单
4. 修复记录（缺陷ID → 改动文件 → 验证方式）
5. 遗留风险（本轮未解决的，写清影响与计划）
