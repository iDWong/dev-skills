# 开发规范与约束（阶段 2 落地清单）

> 规范要**落成项目里的真实文件**，不是口头约定。下面每一项都给了落盘位置。
> 文档类产出统一落 `dev/`（见 SKILL.md「落盘目录」）；工程类配置跟着各子项目根走。

## 1. 必须落盘的文件

| 文件 | 位置 | 内容 |
|---|---|---|
| `README-DEV.md` | 各子项目根（`dev/code/<子项目>/`） | 目录约定、命名规范、路由方式、Mock 约定、设计补全项、与设计稿的偏差记录 |
| `.env.example` | 各子项目根（`dev/code/<子项目>/`） | 全部环境变量 + 用途 + 示例值 + 是否必填（**真实值不进仓库**） |
| lint/format 配置 | 各子项目根（`dev/code/<子项目>/`） | ESLint + Prettier / golangci-lint + gofmt / ruff + black / Checkstyle |
| `openapi.yaml` 或 Swagger 注解 | 后端（`dev/code/server/`） | 接口契约，前端据此生成类型 |
| 错误码表 | `dev/design/error-codes.md` | code / 含义 / HTTP 状态 / 前端提示文案 |
| `docker-compose.yml` + `Dockerfile` | **仓库根**（编排）/ 各服务（`dev/code/<服务>/Dockerfile`） | 一键起全套依赖 |
| 数据库迁移脚本 | 后端子项目内 `dev/code/<服务>/migrations/` 或 `db/` | 可重复执行、含种子数据脚本 |
| CI 配置 | `.github/workflows/` 等 | lint + test + build 三步 |

## 2. 代码质量

- **提交规范**：Conventional Commits（`feat:` `fix:` `refactor:` `test:` `docs:` `chore:`）
- **分支策略**：Trunk-Based（短生命周期 feature 分支，及时合回）或 Git Flow，阶段 2 二选一写进 `README-DEV.md`
- **命名**：跟随项目既有风格；新项目定一次并写进 `README-DEV.md`，不要一个仓库两种风格
- **禁止项**：写死的假数据（要走 mock 层并可一键切真接口）、遗留 `TODO`/`FIXME` 当交付物、
  `console.log` 调试残留、注释掉的旧代码整块留存
- **复用优先**：新增工具函数前先搜仓库有没有同名同义实现

## 3. 设计稿 1:1 对齐（硬性）

逐页核对，核对项：

| 类别 | 核对点 |
|---|---|
| 色彩 | 主色/辅助色/语义色（成功/警告/危险/信息）的**具体色值**，深浅两套主题 |
| 字体 | 字族、字号、字重、行高、字间距 |
| 间距 | 页边距、卡片内边距、组件间距（是否遵循 4/8 栅格） |
| 形状 | 圆角、边框、阴影层级 |
| 图标 | 图标库来源、尺寸、线宽、颜色 |
| 状态 | default / hover / active / focus / disabled / loading / empty / error 八种 |
| 响应式 | 断点、栅格列数、移动端安全区（刘海/底部 Home 条） |
| 动效 | 时长、缓动曲线、是否响应 `prefers-reduced-motion` |

**设计缺失时自动补全**，补全项记进 `README-DEV.md` 的「设计补全项」小节，包含：
缺什么、按什么规则补的、需不需要设计回补。

**偏差书面说明**格式：`页面/组件 | 设计要求 | 实际实现 | 原因 | 影响 | 是否需回补设计`。

## 4. 第三方依赖引入

引入任何新依赖，在汇报里给出：

```
库名@版本 | 用途 | 选型理由（相比手写/替代品的优势）| 体积影响 | 许可证 | 维护状况（最近发布时间）
```

红线：GPL 类传染性许可证进商业闭源产品前必须先问用户；半年以上无维护且有已知漏洞的库不引入。

## 5. 安全与合规基线（每模块自检）

- [ ] **入参校验**：所有外部输入服务端二次校验（不信任前端），含类型、长度、范围、枚举
- [ ] **防注入**：SQL 参数化 / ORM，禁止字符串拼 SQL；富文本输出做 XSS 过滤
- [ ] **越权（IDOR）**：每个按 id 取数的接口都校验「这条数据是不是当前用户/租户的」
- [ ] **鉴权**：管理端菜单前端隐藏只是体验，**后端每个接口必须独立鉴权**
- [ ] **敏感信息**：密码走 bcrypt/argon2；手机号、身份证、银行卡加密存储 + 展示脱敏
- [ ] **限流**：登录、短信验证码、支付等接口做频率限制
- [ ] **日志脱敏**：日志里不出现密码、token、完整证件号
- [ ] **密钥管理**：全部走环境变量；仓库里只有 `.env.example`
- [ ] **文件上传**：类型白名单 + 大小限制 + 重命名存储 + 不可执行目录
- [ ] **合规**：隐私协议、用户注销、数据导出、Cookie 同意（按项目所在地区与 SRS 要求）
