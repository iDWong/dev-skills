# STRIDE 逐边界检查项

> 用法：**每条信任边界**过一遍下面六组。命中就写成一条威胁（带边界名、可能性、影响）。
> 只写这个系统真实存在的，不要把清单抄成结论。

## S — Spoofing（冒充身份）

- 会话凭据：怎么签发、有效期、能否吊销；退出登录是服务端失效还是只删本地
- token 重放：有没有一次性 nonce／时间戳；换设备、换 IP 是否要重新认证
- 服务间调用：内网服务之间是否互信到"谁都能调"；有没有 mTLS／服务令牌
- 第三方回调（支付、OAuth、Webhook）：签名验证、时间窗、来源 IP 白名单
- 找回密码 / 验证码：能否枚举账号、验证码是否可爆破（次数、频率、有效期）

## T — Tampering（篡改）

- 客户端传来的价格、数量、折扣、角色、状态 —— 服务端是否重新计算而不是信任入参
- 订单/审核状态机：能否跨状态直接跳转（把 `status` 直接改成 `approved`）
- 文件上传：类型白名单（按内容而非扩展名）、大小上限、存储路径不可控、不落在可执行目录
- 批量接口：id 列表里混入他人 id 会怎样
- 缓存与消息：能否伪造缓存 key／消息体影响他人

## R — Repudiation（抵赖）

- 敏感操作（删除、导出、改他人数据、权限变更、金额变更）是否留操作日志
- 日志内容：谁、何时、从哪、改了什么（前后值）；日志能否被业务代码改写或删除
- 时间戳来源统一（服务端时间，不是客户端传的）
- 留存期限是否满足合规要求（写进 SRS 非功能章节）

## I — Information Disclosure（信息泄露）

- **越权读（IDOR）**：按 id 取单条是否校验归属／租户；列表接口是否按数据范围过滤
- 错误信息：是否把堆栈、SQL、内部路径、字段名返回给前端；"不存在"与"无权限"是否产生信息差
- 日志与埋点脱敏：手机号、身份证、地址、token、完整请求体
- 导出功能：导出范围是否受权限约束；文件链接是否可被猜测／长期有效
- **数据外发**：是否把用户内容发给第三方（生成式 API、统计 SDK、错误上报）——在文档里写明**发了什么、发给谁**
- 前端：源码里的内网地址、测试账号、注释掉的接口

## D — Denial of Service（拒绝服务）

- 无界查询：没有分页上限、没有时间窗、允许 `pageSize=100000`
- 大对象：上传大小、导出行数、富文本长度、图片尺寸上限
- 重试风暴：客户端失败重试没有退避；服务端重试没有上限
- 限流：按 IP / 按账号 / 按接口三层，写明阈值；登录、验证码、导出是重点
- 资源耗尽：连接池、线程、临时文件、定时任务堆积
- 第三方依赖挂掉时的降级（超时值、熔断、兜底返回）

## E — Elevation of Privilege（权限提升）

- 权限矩阵的每个「否」格子是否在后端有对应校验（**前端隐藏按钮不算**）
- 管理端接口是否与用户端共用鉴权中间件；有没有"只在路由层配了角色"的接口
- 越权写：改他人数据、改自己角色、给自己加权限点
- 多租户：租户 id 从哪来（**必须服务端会话里取，不能信前端传**）
- 内部/调试接口：是否随生产构建暴露；开关默认关

## 可能性 × 影响（定优先级用）

| | 影响低 | 影响中 | 影响高 |
|---|---|---|---|
| **可能性高** | 中 | 高 | **必须在阶段 7 前解决** |
| **可能性中** | 低 | 中 | 高 |
| **可能性低** | 低 | 低 | 中（写进残余风险并给应对） |

可能性判据：无需认证即可触发 = 高；需要普通账号 = 中；需要管理员或物理接触 = 低。
影响判据：数据错误/资金损失/大范围泄露 = 高；单用户数据泄露或功能不可用 = 中；体验问题 = 低。
