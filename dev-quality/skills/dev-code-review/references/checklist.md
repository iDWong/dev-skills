# 八维度检查项（评审时逐项过）

> 用法：每个维度过一遍改动集。命中就写成一条意见（带 `file:line`）；**没命中不用写"无问题"**，
> 报告只列真发现的东西。维度里标 🔴 的是致命／严重候选，优先看。

## 1. 正确性与规格一致

- 🔴 字段名、类型、必填、默认值与 SRS 字段表／详细设计表结构逐项对得上
- 🔴 枚举值与状态流转：新增状态有没有漏改状态机、有没有从终态回跳
- 边界值：0、空串、null、超长、超大数、负数、首尾页、时区与跨天
- 计算口径：金额精度与取整方向、百分比分母、统计时间窗
- 前后端契约两侧一致：响应体字段、可空性、分页参数命名

## 2. 并发与事务

- 🔴 事务边界：跨表写是否在同一事务；事务里有没有塞 HTTP 调用／长耗时操作
- 🔴 幂等：重复提交、消息重投、用户连点会不会出双份数据（有没有唯一键或幂等键兜底）
- 竞态：读-改-写是否需要乐观锁／行锁；计数器是否用了 `SET x = x + 1` 而不是应用层加一
- 锁粒度与顺序：多把锁的获取顺序是否一致（死锁）；锁的持有时间是否跨了 IO
- 异步任务：失败是否可重试、重试是否幂等、有没有无限重试

## 3. 错误处理

- 🔴 吞异常：`catch` 后只打日志继续往下走，调用方以为成功
- 🔴 日志脱敏：手机号、身份证、token、密码、完整请求体进日志
- 错误码与响应体口径统一（对照详细设计的错误码表），前端能据此给出提示
- 外部调用有超时、有重试上限、重试有退避；超时值不是默认无穷
- 失败路径的资源释放：文件句柄、连接、临时文件、已上传对象

## 4. 权限与数据范围

- 🔴 每个新接口都挂了鉴权；不需要鉴权的要显式说明为什么
- 🔴 越权（IDOR）：按 id 取单条时有没有校验归属／租户；批量接口有没有按数据范围过滤
- 🔴 前端隐藏按钮 ≠ 后端有校验：后台管理类改动尤其常犯
- 角色矩阵：新增角色或权限点是否同步到权限表与初始化脚本
- 敏感操作（导出、删除、改他人数据）是否留操作日志

## 5. 性能

- 🔴 N+1 查询：循环里查库／调接口
- 🔴 无界查询：没有 `LIMIT`、没有时间窗、`SELECT *` 拉全表
- 新查询条件有没有对应索引；索引顺序与查询条件是否匹配
- 请求瀑布：前端串行发多个依赖请求，可并行或合并
- 大列表渲染：是否虚拟滚动／分页；一次性塞进内存的数据量
- 缓存：key 设计、失效策略、缓存穿透与击穿；改了数据有没有对应失效

## 6. 可读与复用

- 重复实现：新加的工具函数仓库里是否已有同义实现（先搜再写）
- 分层与依赖方向：handler 里写业务、domain 依赖了 store 的具体实现、跨层直调
- 命名与既有风格一致；同一概念在两端别用两个词
- 圈复杂度：一个函数里三层以上嵌套分支，考虑拆
- 死代码、注释掉的旧实现、改完没删的过渡兼容分支

## 7. 测试

- 改动有没有对应用例；只加了 happy path 的算"覆盖不足"
- 异常分支（参数非法、未授权、越权、不存在、超时）是否有用例
- 测试是否真断言：只跑不断言、断言 `not null`、断言与实现同源（把 bug 一起固化）
- 集成测试被环境变量跳过时，有没有在报告里标"未执行"而不是"通过"
- 数据库迁移是否可重复执行（跑两次不报错）

## 8. 交付卫生

- 🔴 硬编码密钥、token、内网地址；应该走环境变量与 `.env.example`
- 🔴 写死的假数据混进生产路径（mock 层要能一键切真接口）
- 遗留 `TODO`／`FIXME` 当交付物；`console.log`／`fmt.Println` 调试残留
- 与设计稿的偏差没有书面说明（色值、间距、八种交互状态）
- 新依赖：有没有说明选型理由、版本是否钉死、许可证与体积影响
